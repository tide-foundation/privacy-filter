# Tide · Cleanse me!

An unauthenticated, localhost-only Next.js app for sanitizing PDF and Word (DOCX) documents with [OpenAI Privacy Filter](https://github.com/openai/privacy-filter). No paid API or cloud inference is used.

## Run locally

Requirements: Node.js 20.9+ (22 recommended), Python 3.10+, Git, enough RAM/disk for the model and PyTorch. CPU is the default; CUDA is optional. Initial dependency installation and model download require internet access.

```bash
npm install
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
# Optional: choose the smaller CPU-only PyTorch build before installing the model
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -r backend/requirements-model.txt
```

Start the Python service in one terminal:

```bash
OPF_DEVICE=cpu .venv/bin/uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

Start the interface in another:

```bash
npm run dev
```

Open http://localhost:3000. If port 3000 is occupied, use `npm run dev -- --port 3001` and open http://localhost:3001. Upload a `.docx` or `.pdf`, choose placeholders or synthetic data, then select **Cleanse**. The library updates automatically and offers text preview plus DOCX, PDF, and TXT downloads. Delete removes all three outputs and the database record. There is no login.

The model loads on the first job and stays in memory. Upstream downloads its checkpoint to `~/.opf/privacy_filter` if needed. To use existing weights and avoid a runtime download:

```bash
OPF_CHECKPOINT=/absolute/path/to/checkpoint OPF_DEVICE=cpu \
  .venv/bin/uvicorn backend.app:app --host 127.0.0.1 --port 8000
```

For NVIDIA GPUs, install a compatible PyTorch/CUDA build and set `OPF_DEVICE=cuda`. The upstream API currently accepts `cpu` or `cuda`; this app does not assume Apple MPS support. Python settings are shell environment variables, not automatically loaded from `.env.local`. On Windows, use WSL or adapt venv paths and environment syntax for PowerShell.

Production frontend: `npm run build && npm start`, alongside the same Python service. Keep one Python worker: the model and processing queue are deliberately shared inside that process. Do not enable uvicorn reload during processing.

## What the app does

1. Accepts a PDF/DOCX of at most 20 MB; validates its readable content.
2. Maps PDF characters to their original coordinates or DOCX text to its original XML nodes (including tables, headers, footers, text boxes and footnotes/endnotes), with a 200,000-character limit (PDFs: 250 pages).
3. Runs `opf.OPF.redact()` locally, using all eight labels: `private_person`, `private_address`, `private_email`, `private_phone`, `private_date`, `private_url`, `account_number`, `secret`.
4. Requires exact alignment between the model input and returned text, then uses its character spans to apply friendly labels (`[Name]`, `[Date]`, `[Phone Number]`, etc.) or deliberately fictional replacements. Repeated values of the same category receive the same replacement within one document. Synthetic data is generated by the application; the model only detects spans. Dummy examples are not intended to pass financial/account validation or preserve date relationships.
5. Saves a modified copy in the original format, plus rebuilt alternate-format and TXT exports, and saves counts, processing state and timestamps in SQLite. The source filename is not retained; library documents have generated IDs.

## Output fidelity and limits

New uploads try to preserve the original document structure in the **matching-format download**: DOCX for a Word upload, PDF for a PDF upload. The other format is a rebuilt text conversion; TXT and the preview show extracted text. Hover a download button to see which is which. Existing outputs are unchanged; upload the original again to produce a layout-preserving copy. The source file on your machine is never overwritten.

- **Word:** replacements edit existing XML text nodes, retaining paragraph/run styling, page setup, tables, headers, footers, notes, text boxes and images. A replacement spanning multiple differently styled runs inherits the first run's style. Longer replacements can reflow lines/pages. Comments, deleted revision text, field instructions, external hyperlink destinations, custom XML and document properties are removed. Embedded objects, macros, charts, SmartArt and embedded HTML are rejected rather than silently copied without scanning.
- **PDF:** detected glyphs are physically removed using redaction and replacements are written into the same locations. Page geometry and unaffected text/vector artwork stay in place. Replacement text uses a matching standard font family/style/color, reducing the font size if necessary. Exact embedded-font matching is not guaranteed. If a replacement cannot fit at a legible size (6 pt minimum), uses unsupported rotated text, or native export otherwise fails, the job completes with a clean text rewrite instead. A brief note identifies this fallback. Native export writes to a temporary file so a failed or partial attempt cannot damage the clean outputs. Interactive forms must be flattened first. Metadata, annotations, attachments, scripts, links and bookmarks are removed. The file is saved afresh with garbage collection, rather than appending revisions containing the old text.
- **Images:** preserved in native exports and not scanned by this text-only model; the document shows a warning if it contains images. PDF image pixels beneath detected redactions are blanked too. Scanned image-only pages need local OCR first. Keeping images can retain sensitive visual information and image metadata that this text workflow does not detect.
- Limits remain 20 MB per upload, 200,000 extracted characters, and 250 PDF pages. Legacy `.doc` needs conversion to `.docx`. Encrypted PDFs are unsupported.

Original uploads are held temporarily in process memory and are not intentionally written to storage. Detected originals and replacement mappings are not persisted. Only sanitized content is saved, but **model misses can leave sensitive text in the outputs**. Review the preview before sharing. This is detection and substitution, not a guarantee of anonymization. Deletion removes application files and records, not forensic copies from filesystem snapshots, backups, or browser downloads.

Output directory: `./data/<document-id>/sanitized.{docx,pdf,txt}`; metadata: `./data/documents.sqlite3`. Override the root with `PRIVACY_DATA_DIR`. These are ignored by Git. First-run checkpoint downloads go to the upstream model cache, not the document directory.

Up to three jobs can be admitted, with inference serialized to avoid loading duplicate models. The queue is in memory; interrupted jobs are marked failed after restart and must be uploaded again. No external fonts, analytics or document APIs are used. Both services bind to loopback, and the browser proxy restricts cross-origin access. This unauthenticated app is intended only for a trusted local machine, not network deployment.

## Validation

`backend/requirements.lock.txt` records the verified Linux CPU environment. To reproduce it, install CPU PyTorch from the command above, then install the lock file using pip (the `+cpu` wheel must already be present).

```bash
npm run typecheck
npm run build
.venv/bin/python -m pytest backend/tests -q
# With the frontend running:
npx playwright install chromium
npm run test:browser
# Or: BASE_URL=http://127.0.0.1:3001 npm run test:browser
# Optional, with both services running and the model installed:
BASE_URL=http://127.0.0.1:3001 .venv/bin/python scripts/model-smoke.py
```

Pipeline/API tests inject a deterministic detector and do not claim to measure the real model's accuracy. Real inference requires installing the separate model requirements and downloading the checkpoint. The upstream package is pinned to commit `f7f00ca7fb869683eb732c010299d901457f19c3`.

## Synthetic replacement logic

The model detects spans and labels; it does not generate synthetic identities. The application uses one in-memory map per document, keyed by `(category, original_text.casefold())`. Each new key gets an incrementing index. Templates produce `Alex Example N`, `N Example Street, Sampletown`, reserved example email/URL domains, fictional-range US phone numbers, January 2000 dates, and `DEMO-…` / `SYNTHETIC-…` values for accounts and secrets. A random per-document token is included in emails, URLs, accounts and secrets. The same value/category reuses its replacement within that document, including headers and footers.

These templates do not preserve locale, validation checksums, date intervals, identity relationships or name aliases. Dates and phone numbers cycle through their template ranges and can collide for different values. Case differences are ignored; whitespace differences are not. The original-to-replacement mapping is discarded after processing.
